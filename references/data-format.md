# 審片台頁面資料 D 的格式（給 AI 代理看）

`assets/page.tpl.html` 裡有一行 `const D = __DATA__;`，`scripts/make_board.py` 把下面這個 JSON 物件填進去。
`--extra extra.json` 的內容會用 `dict.update` 合併進 D（頂層鍵整個蓋掉），**唯一例外是 `kinds`：是逐個類別合併**，沒列到的類別保留自動產生的。
以下每個欄位都是從 `page.tpl.html` 的程式碼確認過的（括號內是模板用到它的地方）。時間單位一律是**秒**（可小數）。

## 頂層欄位

| 欄位 | 型別 | 必填 | 用途 |
|---|---|---|---|
| `title` | 字串 | 否（預設「審片台」） | 片名，顯示在 h1（沒有 props 時尾巴會加「｜審片台」）和瀏覽器分頁標題 |
| `ver` | 字串 | **是** | 版本名。本機暫存的鍵前綴 `<board 或 title>|<ver>:`、意見的 `ver` 欄位、整版核准都用它；改版請換新的 |
| `total` | 數字 | **是** | 影片總秒數。時間軸長度＝`total × 32` 像素；縮圖索引上限也靠它 |
| `pic` | 陣列 | **是**，至少 1 筆 | 鏡頭清單（下節）。必須從 `s:0` 開始、首尾相接蓋滿 `total`；找不到所在鏡頭時模板會退回最後一個鏡頭 |
| `kinds` | 物件 | 否（預設 `{}`） | 類別代碼 → `[名稱, 怎麼做的, 素材來源, 顏色(選填)]`。`怎麼做的`、`素材來源` 是鏡頭沒填 `how`／`src` 時的預設文字。顏色可填任何 CSS 色（`"#ff9ac4"`）；沒填時，代碼是模板內建的（`aiv aii realv real fig photo b3d bvid code card warn`）就用內建色，否則用灰色 `--card`。`pic[].k` 沒列在 `kinds` 裡也不會當掉（名稱顯示代碼本身） |
| `agent` | 字串 | 否（預設 `AI`） | 介面上「傳給 ○○」、回覆者名稱、提示文字裡的 AI 稱呼 |
| `voLabel` | 字串 | 否（預設「旁白／台詞」） | 說明欄裡 `vo` 那一列的名稱（也用在提案裡「這句」那一列） |
| `hint` | 字串 | 否 | 標題旁的提示文字；沒給就用預設（有 props 時用提案專用的預設） |
| `chap` | 陣列 | 否（預設 `[]`） | 章節：`[秒, 章名]`。在全片總覽畫細線、魚骨上畫章名標籤、說明欄顯示「目前在哪一章」 |
| `subs` | 陣列 | 否（預設 `[]`） | 字幕：`[開始, 結束, 文字]`。魚骨的字幕區、說明欄的「字幕」列 |
| `vo` | 陣列 | 否（預設 `[]`） | 旁白／台詞：`[開始, 持續秒數, 文字]`（注意第二個是**長度**不是結束時間）。說明欄的 `voLabel` 列 |
| `sfx` | 陣列 | 否（預設 `[]`） | 音效點：`[時間, 名稱]`。魚骨聲音區的菱形標記；落在該鏡頭內的會列在說明欄「音效」 |
| `music` | 陣列 | 否（預設 `[]`） | 配樂段：`[開始, 結束, 名稱]`。名稱含「靜音」的段落畫成斜線樣式 |
| `wave` | 陣列 | 否（預設 `[]`） | 音量波形：整數 0–99，**每 0.25 秒一格**（長度應為 `total×4`）。沒聲音軌就全 0 |
| `props` | 陣列 | 否 | 「花錢前提案」（下節）。有給（長度>0）時：顯示提案區、整版核准按鈕**不出現**、標題與提示改用提案版 |
| `notes` | 字串陣列 | 否 | 只在有 `props` 時顯示的提案說明（每則一條） |
| `openings` | 陣列 | 否 | 開場方案：`[{id, title, text, meta}]`，審片的人可選一個，結果存在 `choices.opening` |
| `mode` | 字串 | 否 | 只有 `"new"` 有作用：分鏡草稿用（說明欄多一列「費用」、提案文案改成「分鏡草圖」） |
| `twd` | 數字 | 否 | 提案費用換算：每「點」折多少錢；有給才會在點數後顯示「（約 …）」 |
| `unit` | 字串 | 否（預設 `NT$`） | 上面金額的幣別符號 |
| `direct` | 布林 | 否 | `true`＝整支片一個檔 `v0.mp4`（瀏覽器邊播邊抓）。`make_board.py` 一律設 `true`。沒設時模板會把 `v<k>.mp4` 整段 fetch 成 blob（需要 `chunk` 分段） |
| `chunk` | 數字 | 否（預設 100000） | 影片分段長度（秒）。`direct` 模式下設得比影片長就等於不分段 |
| `mbase` | 字串 | 否（預設 `""`） | 縮圖表 `t*.jpg` 和影片 `v*.mp4` 的網址前綴 |
| `pub` | 布林 | 否 | `true`＝**雲端模式**（見下）。由 `cloud/build_site.py` 注入，不要自己設 |
| `board` | 字串 | `pub` 時必填 | 雲端審片台名稱（`/api/store?b=` 的值，小寫英數與減號，≤40 字）。由 `build_site.py` 注入 |
| `nav` | 陣列 | 否 | 頁首導覽：`[{label, href, on}]`。由 `build_site.py` 注入 |

`make_board.py` 實際產生的 D 還有 `direct:true`、`chunk:100000`、`agent`、`kinds`（自動補色）、`vo`（由字幕檔轉來）、空的 `chap/sfx/music`。

### `pic[]`：一個鏡頭

| 欄位 | 型別 | 必填 | 用途 |
|---|---|---|---|
| `s` | 數字 | **是** | 開始秒 |
| `d` | 數字 | **是** | 持續秒數（`s+d` ＝下一鏡頭的 `s`） |
| `k` | 字串 | **是** | 類別代碼（對應 `kinds`） |
| `t` | 字串 | **是** | 鏡頭名 |
| `how` | 字串 | 否 | 「怎麼做的」；沒填用 `kinds[k][1]` |
| `src` | 字串 | 否 | 「來源」；沒填用 `kinds[k][2]` |
| `note` | 字串 | 否 | 「備註」列（`make_board.py` 的 shots `note` 對應到這裡） |
| `desc` | 字串 | 否 | 「畫面內容」列 |
| `f` | 字串 | 否 | 附在「停留」列後的構圖說明 |
| `u`、`n` | 整數 | 否 | 這個素材第 `u` 次出現、全片共用 `n` 次；`n>1` 時鏡頭卡右上角顯示 `u/n`（`n>=4` 標紅），說明欄多一列「重複使用」 |
| `o` | 字串 | 否 | 「疊加字卡」列 |
| `sk` | 字串 | 否 | 「這格草圖」列 |
| `cost` | 數字 | 否 | 只在 `mode:"new"` 時用：「費用」列（0 顯示「0 元」） |
| `b` | 任意 | 否 | 模板不讀（舊專案留下的鏡頭編號），可省略 |

### `props[]`：花錢前提案（選用）

必填：`id`（字串，如 `"P1"`）、`rev`（整數，內容改過就加 1，舊核准即失效）、`segs`（整數陣列，**`pic` 的索引**，兩個提案不能搶同一個鏡頭）、`t`（開始秒）、`d`（佔幾秒）、`cost`（點數）、`title`、`cur`（現在的畫面描述）。
選填：`kind`（`"video"` 顯示「AI 影片 5 秒」，其他顯示「AI 圖片」）、`label`（蓋掉上面的預設標題）、`desc`、`move`、`zh`（這句旁白）、`basis`、`risk`、`note`（這版改了什麼）。
審片的人對每個提案可「核准這一項」、「送出意見」（意見的 `cat` 固定 `"提案"`，並帶 `prop`、`rev`）。

## 三種儲存模式

模板啟動時依序判斷：`D.pub` → 雲端模式；否則有 `window.claude.use` → Artifact 模式；否則本機模式。連線失敗也會退回本機模式。

### 意見的資料列（三種模式共通）

```
t        數字  秒（取到 0.1）；整片意見是 -1
seg      整數  鏡頭編號（1 起算）；整片意見是 -1
segTitle 字串  鏡頭名；整片意見是「整支片」；提案意見是「<id> <提案名>」
cat      字串  畫面／聲音／字幕／節奏／其他／提案；「＋標記這裡」先標記、還沒寫時是 ""
text     字串  意見內容；標記還沒寫時是 ""
at       字串  ISO 時間
ver      字串  寫下當時的 D.ver
done     布林  AI 處理完可改成 true（介面顯示「✓ 已處理」）
whole    布林  （選填）「整片都要檢查」：整支片有類似問題的地方都要看
reply    字串  （選填）AI 的回覆（介面顯示「<agent>：…」）
prop,rev       （只有提案意見）提案 id 與版次
```

核准資料列：整版核准存在 `approvals.version`＝`{ok:true, ver, at, title:"整版核准"}`（只有沒有 props 的審片台）；提案核准存在 `approvals.<提案id>`＝`{ok, rev, kind, cost, title, at, ver}`；開場選擇存在 `choices.opening`＝`{pick, at, ver}`。核准只在 `ver`（提案是 `rev`）和目前一致時才算數。

### 1. 本機模式（沒有後台，最簡單，`make_board.py` 的預設）

- 意見存在瀏覽器 `localStorage`，鍵前綴 `<board 或 title>|<ver>:`：`cms`（意見陣列，每則 `id` 是 `l<毫秒時間戳>`）、`appr`（核准）、`pick`（開場）、`drafts`／`draft`（還沒存的字）。
- 「傳給 ○○」按鈕在這個模式隱藏。審片的人點開「我寫的意見」→ 按**「複製全部意見」**→ 貼回對話給 AI。AI 收到的就是下面這種文字。
- 也可以直接讀 `localStorage` 的 `<title>|<ver>:cms`（要在審片的人的瀏覽器裡）。

### 2. 雲端模式（`D.pub`，要部署 `cloud/`）

- 意見存在網站後台 `/api/store`（Netlify Blobs）：`GET /api/store?b=<board>` 回整份 `{comments:{<id>:資料列}, approvals:{…}, choices:{…}, meta:{…}}`；`POST` body `{b, op:"set"|"merge"|"del", c:集合名, id, d}`，回改完的整份。`meta.sent={at, n}` 記錄最後一次「傳給 ○○」的時間。
- 審片的人按**「傳給 ○○」**：先把標記裡寫好的字存進後台，再送出一筆 Netlify 表單 `review`：`board`、`sent`（ISO 時間）、`summary`（意見文字，≤6000 位元組）、`payload`（整份 JSON，≤60000 字元）。**不會叫醒 AI**。
- AI 讀法：沒設密碼就直接 `GET /api/store?b=<board>`；設了密碼只能讀 Netlify 表單。寫回處理結果：`POST` `{b, op:"merge", c:"comments", id, d:{done:true, reply:"…"}}`。
- 每 30 秒自動重新讀一次（輸入框有游標時不讀）。

真實跑出來的後台資料（用 `cloud/` 的 `/api/store` 協定的本機模擬跑出，頁面是 `build_site.py` 產生的，操作是：在 5.2 秒寫一則意見、再按一次「＋標記這裡」、按「傳給 助理」）：

```json
{"approvals":{},"choices":{},
 "comments":{
  "cmwovw190gsy3":{"at":"2026-11-20T11:16:35.796Z","cat":"畫面","done":false,"seg":2,"segTitle":"過場字卡","t":5.2,"text":"雲端：字幕太快","ver":"t-v1"},
  "cmwovw1myjdaf":{"at":"2026-11-20T11:16:36.298Z","cat":"","done":false,"seg":2,"segTitle":"過場字卡","t":5.2,"text":"","ver":"t-v1"}},
 "meta":{"sent":{"at":"2026-11-20T11:16:36.800Z","n":2}}}
```

對應的表單 `summary`：

```
【t-v1】審片台傳來：意見 2 則（其中 1 個標記還沒寫）；整版還沒核准。完整內容在審片台資料庫。
[0:05] 雲端：字幕太快
[0:05] （未寫）
```

### 3. Artifact 模式（`window.claude`）

- 頁面放在 Claude Artifact 裡時，模板用 `window.claude.use('db')` 取得資料庫（集合 `comments`／`approvals`／`choices`，資料列格式同上，`id` 是資料庫的文件 id），用 `window.claude.use('comments')` 的 `canSendToClaude()`、`anchorFor(el)`、`sendToClaude({anchor, text})` 把意見文字送回對話；AI 之後用 ArtifactData 讀 `comments` 集合。
- 送回對話的文字是下面「匯出的意見文字」的格式，上限 3600 位元組，超過會在結尾寫「…（其餘請讀資料庫）」。
- **這個模式本次沒有實測**（需要 Artifact 環境）。注意：模板現在是完整 HTML 文件（含 doctype、`<head>`）；若要貼成 Artifact，請確認平台是否會再包一層，必要時把 `<head>` 內容併進平台的外殼。

## 匯出的意見文字

格式（`sendText()`）：

```
【<ver>】審片台傳來：意見 N 則[（其中 K 個標記還沒寫）][；開場選提案 X|（還沒選）][；已核准 a／b 項（id、id，共 N 點）][；整版已核准|還沒核准]。完整內容在審片台資料庫。
[m:ss｜鏡頭 N〈鏡頭名〉[｜素材來源][ 提案id][｜整片都要檢查]] 意見內容        ← 每則一行，依時間由小到大；整片意見排最前面，時間顯示「整片」、不帶鏡頭
```

- 括號 `[ ]` 內的片段是有條件才出現的。「複製全部意見」會把「完整內容在審片台資料庫。」那句換成句點，其餘相同。
- 每行帶時間、鏡頭編號與鏡頭名；鏡頭有填 `src` 時再帶素材來源。沒有類別（`cat`）；時間只到整數秒，要類別或精確的 `t` 得讀 `localStorage` 或資料庫的資料列。
- 沒寫內容的標記顯示「（未寫）」。

真實範例（本機模式，三則意見＋整版核准，從「複製全部意見」的輸出原樣貼上）：

```
【t-v1】審片台傳來：意見 3 則；整版已核准。
[整片] 整片的色調偏冷
[0:05] 這裡字幕太快
[0:09] 標記後補的字
```

上面兩個範例是加上鏡頭名之前跑的。現在的輸出（示範片〈山頂咖啡｜開幕預告〉，兩則意見，實際跑出）：

```
【v1】審片台傳來：意見 2 則；整版還沒核准。
[0:13｜鏡頭 4〈一杯咖啡的 4 分鐘〉｜自製，無外部素材] 橫條長出來太慢
[0:19｜鏡頭 5〈店門口〉｜自製，無外部素材] 招牌的字太小
```

提案版的標頭範例（真實跑出）：`【props-v1】審片台傳來：意見 1 則；開場選提案 1；已核准 1／1 項（P1，共 2 點）。完整內容在審片台資料庫。`
